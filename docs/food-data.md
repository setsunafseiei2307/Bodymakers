# 食品データについて

`src/lib/foodData.ts` の2,538食品は、すべて下記から機械的に転記したものです。
**AIによる推測値・補完値は一切含みません。**

## 出典

- 文部科学省「日本食品標準成分表（八訂）増補2023年」第2章（データ）本表
- https://www.mext.go.jp/a_menu/syokuhinseibun/mext_00001.html
- 元ファイル: `20260327-mxt_kagsei-mext-000029402_02.xlsx`（Excel / 約1.9MB / 全2,538食品）
- 数値はすべて **可食部100gあたり**

各食品は成分表の **食品番号** を `id` に、**収載名** を `officialName` に持っています。
アプリ上でも食品詳細に出典と食品番号を表示しており、元データまで遡れます。

### 表示名の方針

使用頻度の高い300食品には、探しやすい表示名を手で当てています
（収載名「こめ [水稲めし] 精白米 うるち米」→ 表示名「ごはん（精白米）」）。
残りは**収載名をそのまま表示名にしています**。言い換えや要約はしません。

どの食品も `officialName` に収載名を、`id` に食品番号を保持しているので、
元データまで遡って確認できます。

### 値が入っていない食品

`09059`「わかめ カットわかめ 水煮の汁」は、成分表そのものが未測定のため
エネルギーとPFCが空です。推測で埋めず、画面では「データなし」と表示します。
食物繊維は145件、食塩相当量は1件が未測定です。

推定値（成分表で括弧付き）を含む食品は1,143件あり、`estimated` に項目名を記録しています。

## 成分表の記号の扱い

| 成分表の表記 | 意味 | データ上の扱い |
|---|---|---|
| `-` | 未測定 | `null` |
| `Tr` | 微量（最小記載量未満） | `0` |
| `(12.3)` | 推定値・借用値 | `12.3`。`estimated` に項目名を記録し、UIに「推定」バッジを出す |
| 空欄 | 該当なし | `null` |

## エネルギーをPFCから再計算してはいけない

八訂ではエネルギーの算出方法が組成成分ベースに変わり、成分ごとに異なる係数を使っています
（食物繊維は約2kcal/g、アルコールは7kcal/g など）。
このため **P×4 + F×9 + C×4 では収載値と一致しません**。

| 食品 | 収載値 | 4/9/4で計算 |
|---|---:|---:|
| ひじき（乾） | 180kcal | 299kcal |
| しいたけ（生） | 25kcal | 41kcal |
| 清酒（普通酒） | 107kcal | 21kcal |

`scaleFood()` はカロリーを再計算せず、収載値をグラム数に比例させるだけです。
この挙動は `src/test/foods.test.ts` で固定しています。

## 絵文字

`emoji` は `string | null` です。該当する絵文字が存在しない食品（豆腐・こんにゃく・しょうゆ・
のり など61件）は `null` にしてあり、UI側は絵文字なしで表示します。
このとき名前の左端がずれないよう、`.food__emoji` は空でも幅を確保します。

「近いけれど別の食品」の絵文字は当てません（例: カリフラワーに🥦は使わない）。

## データの検証

`src/test/foods-source.json` は元Excelから抽出した値をそのまま保持しています。
`src/test/foods.test.ts` が全2,538食品 × 6成分をこのファイルと突き合わせるため、
`foodData.ts` を手で書き換えると、どの食品のどの項目がずれたかを名指しでテストが落とします。

```bash
npm test
```

## 再生成の手順

成分表が更新されたとき、または収録食品を入れ替えたいときの手順です。
Python 3 と `openpyxl` が必要です。

```bash
pip install openpyxl
```

1. 上記URLから第2章（データ）のExcelを `scripts/food-data/raw/seibunhyo2023.xlsx` として保存する
2. `scripts/food-data/` で以下を順に実行する

```bash
python3 extract.py    # Excel -> raw/all_foods.json（全2,538食品）
python3 build_all.py  # 表示名・絵文字・カテゴリを付与 -> raw/selected_foods.json
python3 emit_ts.py    # -> src/lib/foodData.ts と src/test/foods-source.json
```

3. `npm test` で全件通ることを確認する

表示名・絵文字を変えるときは `names.py` の `DISPLAY_NAME` / `EMOJI_RULES` / `EMOJI_OVERRIDE` を編集します。
`DISPLAY_NAME` に無い食品は収載名がそのまま使われるので、追加は任意です。

`raw/` の中身（Excelと中間JSON）は `.gitignore` で除外しています。
Excel 1.9MB と中間JSON 数百KBをリポジトリに入れる価値がないためです。

## 出力形式について

2,538件をオブジェクトリテラルで書くと 579KB になり、そのぶんJSのパースが要ります。
キー名を持たないタプル形式にして 231KB（gzip 54KB）に抑え、
モジュール読み込み時にオブジェクトへ展開しています（展開は数ミリ秒）。

`src/test/foods-source.json` は `foodData.ts` とは**別経路**（生の `all_foods.json`）から
書き出しています。同じ経路で作ると、変換にバグがあっても両方が同じように壊れて
検証にならないためです。

### 絵文字ルールの落とし穴

キーワードで自動付与しているため、部分一致で誤爆します。実際に踏んだものを残しておきます。

- `もも` が「牛もも」「鶏もも」に一致して🍑になった → 行頭に固定（`^もも（`）
- `^鶏` が「鶏卵」に、`^牛` が「牛乳」に一致した → 卵・乳のルールを肉より先に置いた
- 「マヨネーズ（全卵型）」が`卵`に、「大豆もやし」が`大豆`に一致した → `EMOJI_OVERRIDE` で個別に打ち消し

追加・変更したら、`foods.test.ts` の「紛らわしい名前でも正しい絵文字が付いている」を確認してください。
